Yes, absolutely. You can create custom subagents in Claude Code purely via Markdown files with YAML frontmatter—without writing a single line of Python or TypeScript code. [1] (https://daily.dev/posts/claude-code-subagents-the-feature-everyone-has-and-nobody-uses-right-fjzqfdefe), [2] (https://www.digitalapplied.com/blog/build-claude-code-custom-subagent-step-by-step-2026)
By simply placing Markdown files into your .claude/agents/ folder, Claude Code dynamically instantiates them, gives them isolated context windows, and binds specific tools to them. [1] (https://www.geeksforgeeks.org/artificial-intelligence/claude-code-subagents/), [2] (https://claude.com/resources/articles/subagents-in-claude-code), [3] (https://daily.dev/posts/claude-code-subagents-the-feature-everyone-has-and-nobody-uses-right-fjzqfdefe)
The core trick to orchestrating a sequential Plan ➔ Generate ➔ Evaluate pipeline without code is using Description Triggers and forcing the subagents to read/write from disk. [1] (https://www.digitalapplied.com/blog/build-claude-code-custom-subagent-step-by-step-2026)

Step 1: Create the Markdown Agents

Create three separate Markdown files in your project directory at .claude/agents/. [1] (https://claude.com/resources/articles/subagents-in-claude-code), [2] (https://www.digitalapplied.com/blog/build-claude-code-custom-subagent-step-by-step-2026)

1. architect-planner.md

markdown
---
name: architect-planner
description: MUST BE USED first for any feature requests to generate technical specifications, architectural designs, and API contracts.
tools: [Read, Write, Edit, Glob, Grep]
model: sonnet
---
You are an expert Software Architect. Your job is to analyze requirements and write a technical specification file. 

CRITICAL PROTOCOL:
1. Do NOT write application source code.
2. Draft a complete feature specification.
3. Save this specification to `docs/specs.md`.
4. When finished, inform the user that specs.md is ready for the generator.
Use code with caution.

2. code-generator.md

markdown
---
name: code-generator
description: MUST BE USED to write application source code after a specs.md file has been generated or updated.
tools: [Read, Write, Edit, Glob, Grep]
model: sonnet
---
You are an Expert Software Engineer. Your job is to read `docs/specs.md` and project standard files to write the actual source code.

CRITICAL PROTOCOL:
1. Locate and read `docs/specs.md` and your global code standards.
2. Implement the features exactly as described.
3. Write the actual source files into the codebase.
4. When complete, provide a summary of the files you created or edited.
Use code with caution.

3. code-evaluator.md

markdown
---
name: code-evaluator
description: MUST BE USED to perform a strict QA code review on newly generated code against specs.md and style guidelines.
tools: [Read, Glob, Grep]
model: sonnet
---
You are a Strict Senior QA Engineer. You have read-only access to verify code correctness.

CRITICAL PROTOCOL:
1. Compare the newly written application files against `docs/specs.md`.
2. Evaluate the code against your project's coding standards.
3. Provide a clear "PASS" or "FAIL" code review report. 
4. If "FAIL", explicitly list line-by-line what needs to be fixed.
Use code with caution.

Step 2: Zero-Code Orchestration (The Workflow)

Because Claude Code natively routes tasks based on the description fields in your YAML frontmatter, you can orchestrate this entire sequence straight from your terminal chat: [1] (https://www.morphllm.com/subagent), [2] (https://www.digitalapplied.com/blog/build-claude-code-custom-subagent-step-by-step-2026)
1. Trigger Phase 1 (Planning): In your main Claude Code terminal, type your request:"I need a new user registration endpoint. Run the planner agent to create the specification file."
Claude Code reads the prompt, matches the description to architect-planner, spawns it, and that agent automatically saves the architecture blueprint to docs/specs.md.
 [1] (https://www.digitalapplied.com/blog/build-claude-code-custom-subagent-step-by-step-2026), [2] (https://claude.com/resources/articles/subagents-in-claude-code)
2. Trigger Phase 2 (Generation): Once the planner finishes, simply type:"Now pass this to the code generator agent to implement."
Claude Code hands the context off to code-generator, which reads docs/specs.md and builds your codebase.
 [1] (https://www.digitalapplied.com/blog/build-claude-code-custom-subagent-step-by-step-2026)
3. Trigger Phase 3 (Evaluation): Finally, trigger the gatekeeper:"Have the code evaluator agent review the changes."
The evaluator reads the spec file, reads the newly generated source files, and gives you a definitive quality score.
 [1] (https://www.digitalapplied.com/blog/build-claude-code-custom-subagent-step-by-step-2026)
