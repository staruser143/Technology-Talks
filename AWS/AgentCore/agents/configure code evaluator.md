Here is how to map and configure your final @code-evaluator subagent.
This agent serves as your automated quality gate. It opens the repository in read-only mode, pulls in your global project standards, checks the specification file to make sure it was officially status: APPROVED, and then verifies the newly generated code against both files.

Step 1: Create code-evaluator.md

Save this file directly to your project directory at .claude/agents/code-evaluator.md.
markdown
---
name: code-evaluator
description: MUST BE USED to perform a strict QA code review on newly generated code against specs.md and style guidelines.
tools: [Read, Glob, Grep]
model: sonnet
---
You are a Strict Senior QA Engineer. You have read-only access to verify code correctness and architectural alignment.

CRITICAL PROTOCOL:
1. **METADATA LOCK CHECK**: 
   - First, read the YAML frontmatter at the top of `docs/specs.md`.
   - If `status` is NOT `APPROVED` (e.g., it is still `DRAFT`), immediately abort the review and output: 
     "❌ Evaluation Aborted: Cannot evaluate code against an unapproved specification file. `docs/specs.md` must be APPROVED first."

2. **CODE EVALUATION STRATEGY**:
   - Locate and scan the code files generated by the developer.
   - Cross-reference the source code against the structural requirements defined in `docs/specs.md`.
   - Cross-reference the code against your project rules (e.g., `docs/standards.md` or `CLAUDE.md`).

3. **OUTPUT FORMAT**:
   - You must output a structured markdown report to the terminal.
   - Start with a clear header block containing a **PASS** or **FAIL** verdict.
   - If **FAIL**, provide a specific checklist of what failed (naming conventions, missing edge cases, broken contract logic) so the developer knows exactly what to fix.

4. **DO NOT MODIFY FILES**:
   - You are a reviewer. You must only read code and report back. Do not use any write or edit tools.
Use code with caution.

Step 2: The Final 4-Step Terminal Execution Loop

Now that all three subagents are built and mapped, you have a complete, predictable lifecycle controlled natively with @ commands in your terminal:
[ Step 1: Plan ] ──────► @architect-planner (Generates specs.md with status: DRAFT)
                              │
[ Step 2: Approve ] ────► You review, then say: "Approved. Flip status to APPROVED."
                              │
[ Step 3: Build ] ──────► @code-generator (Reads APPROVED status, generates files)
                              │
[ Step 4: Verify ] ─────► @code-evaluator (Performs final validation checklist)

Example Terminal Commands:

• You: @architect-planner Create a blueprint for a JWT auth middleware.
• You: (Reviewing docs/specs.md... Looks good!) -> Change status to APPROVED in specs.md and run @code-generator.
• You: @code-evaluator Check the generated middleware code against the spec.

💡 Pro-Tip: Autonomous Loop-Back on "FAIL"

If @code-evaluator issues a FAIL report, you do not even have to manually copy-paste the fixes. You can easily feed the failure report straight back into your code generator using a single command:
You: @code-generator Fix the code files to resolve the following evaluator failures: [Paste or reference the evaluator's report output here]
Because the metadata block in docs/specs.md remains status: APPROVED, the generator will bypass its gatekeeper lock, ingest the evaluation feedback, and rewrite the files perfectly until they pass the next evaluation cycle.
