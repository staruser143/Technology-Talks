# LangGraph support for Subgraphs
- Yes, LangGraph fully supports subgraphs. A subgraph is a complete, compiled StateGraph that functions as an independent module inside a "**parent graph**". 
- This is a core feature used to build complex, modular, and scalable multi-agent systems. [1, 2, 3] 
## Why Use Subgraphs?
 
* 🧩 **Modular Design**: Keeps the internal logic of individual agents or tasks (like a dedicated coding assistant or specific tool-calling logic) from cluttering the main flow.
* 🔁 **Reusability**: You can build and compile a subgraph once and insert it into multiple parent graphs.
* 📦 **Independent State Management**: Subgraphs can maintain their own isolated state keys, which helps keep local variables private. [2, 4, 5] 

------------------------------
## The Two Patterns for Connecting Subgraphs
Depending on whether your parent graph and subgraph need to share data automatically, we can implement them in one of two ways: [2] 

## 1. Add the Subgraph Directly as a Node (Shared State)
- If the parent graph and the subgraph share the same state keys (for example, a shared messages list), we can pass the compiled subgraph directly into the .add_node() method. It will automatically read from and write to those shared parent state channels. [1] 
- We can integrate a compiled subgraph directly into a parent StateGraph using parent_builder.add_node("node_name", subgraph) if both share matching state schemas. For example: [1, 2] 
```python
from langgraph.graph import START, StateGraphfrom typing_extensions import TypedDict
class SharedState(TypedDict):
    messages: list
    user_id: str
subgraph = subgraph_builder.compile()parent_builder = StateGraph(SharedState)
parent_builder.add_node("specialized_agent", subgraph)
parent_builder.add_edge(START, "specialized_agent")parent_graph = parent_builder.compile()
```

## 2. Invoke the Subgraph Inside a Node Function (Different States)
- If ther subgraph uses a completely different state schema from the parent graph, passing it directly is not supported. 
- Instead, wrap the subgraph invocation inside a standard Python node function, mapping the parent state to the subgraph's expected input and transforming the output back: [2] 

```python
def call_subgraph_node(state: ParentState):
    subgraph_input = {"documents": []} 
    subgraph_output = compiled_subgraph.invoke(subgraph_input)
```

## Tooling Support

* **Persistence**: LangGraph automatically handles subgraph persistence when using a checkpointer with the parent graph, and you can inspect historical states via graph.get_state(config, subgraphs=True). [1] 
* **LangGraph Studio**: Subgraphs appear natively with features like collapsible visual containers, nested expansion, human-in-the-loop tracking, and step-by-step replay. [6]
