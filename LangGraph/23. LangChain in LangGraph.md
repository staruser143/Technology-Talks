LangGraph is an independent, low-level orchestration framework where nodes are standard Python functions and the control flow uses standard Python logic. You do not strictly need LangChain to use LangGraph.
However, pairing LangChain (langchain, langchain-core, and provider packages like langchain-openai) with LangGraph is recommended in specific scenarios where ready-made abstractions eliminate boilerplate:
1. Conversational Chat History & Message Management
 * add_messages Reducer: LangGraph provides the add_messages reducer to automatically append new conversation turns, handle message IDs, and deduplicate updates. This reducer relies directly on LangChain message abstractions (HumanMessage, AIMessage, ToolMessage, SystemMessage).
 * Unified Message Schema: Storing LangChain message objects in your graph state ensures standardized attributes (such as .tool_calls, .content, .response_metadata, and .id), eliminating the need to write custom parsers for disparate model APIs.
2. Multi-Provider LLM Swapping & Tool Binding
 * Provider Agnosticism: Using LangChain model wrappers (such as ChatOpenAI, ChatAnthropic, or ChatGoogleGenerativeAI) lets you switch LLM providers without rewriting node logic or payload formats.
 * Uniform Tool Calling (bind_tools): When building agentic tool loops, LangChain’s .bind_tools() normalizes how tools and JSON schemas are sent to various LLMs.
3. Prebuilt Agentic Patterns (ToolNode & create_react_agent)
 * Prebuilt Tool Execution (ToolNode): LangGraph's prebuilt ToolNode reads AIMessage.tool_calls, executes the corresponding Python functions or tools, and packages the outputs into ToolMessage instances. This integration expects LangChain tool and message definitions.
 * Quick Prototyping: High-level agent factories (like create_react_agent) rely on LangChain models and tools under the hood to bootstrap complete ReAct loops quickly.
4. Advanced Tool Ecosystem & Integrations
 * Pre-Integrated Toolsets: LangChain provides a large library of pre-built integrations (e.g., search engines, SQL database toolkits, web scrapers, vector store retrievers).
 * @tool Decorator: Converting standard Python functions into schemas with parameter validation and automatic docstring extraction is handled directly by langchain_core.tools.tool.
5. Structured Data Extraction (with_structured_output)
 * Pydantic Model Parsing: When an LLM node must return validated JSON matching a Pydantic schema, LangChain’s .with_structured_output(PydanticModel) handles schema injection, tool calling, and response parsing automatically before returning the validated object into state.
When to Skip LangChain and Use Pure LangGraph
You can skip LangChain completely and build pure LangGraph applications when:
 * Deterministic / Non-LLM Pipelines: The workflow processes deterministic data, business rules, or extract-transform-load (ETL) steps without generative models.
 * Direct Vendor SDKs: You prefer using raw provider SDKs (such as official openai or anthropic client libraries) directly inside node functions for minimal dependencies.
 * Zero Abstraction Overhead: You want complete control over request structures, rate limits, raw HTTP calls, or specialized microservice payloads without framework middleware.
