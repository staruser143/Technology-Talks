Dynamic interruption uses LangGraph's interrupt() function inside any node function. Unlike static breakpoints (interrupt_before/interrupt_after) configured at compile time, interrupt() pauses execution right at that line, exposes a prompt payload to the caller, and waits for a value passed back via Command(resume=...).
Step-by-Step Implementation
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver[span_1](start_span)[span_1](end_span)
from langgraph.types import interrupt, Command

# 1. Define State
class PaymentState(TypedDict):
    recipient: str
    amount: float
    confirmed: bool
    status: str

# 2. Node with Dynamic Interruption
def process_payment(state: PaymentState) -> dict:
    print(f"[Node] Checking transfer of ${state['amount']} to {state['recipient']}...")

    # Threshold check: small amounts process automatically, large amounts pause for human input
    if state["amount"] > 1000:
        # Pauses execution and surfaces this payload to the client/caller
        approval = interrupt({
            "message": f"High-value transfer of ${state['amount']} requires approval.",
            "recipient": state["recipient"]
        })
        
        # When resumed, 'approval' holds the value passed in Command(resume=...)
        if not approval:
            return {"confirmed": False, "status": "rejected_by_human"}

    return {"confirmed": True, "status": "completed"}

# 3. Assemble and Compile Graph
builder = StateGraph(PaymentState)
builder.add_node("payment", process_payment)
builder.add_edge(START, "payment")
builder.add_edge("payment", END)

# Dynamic interrupts require a checkpointer to record the paused thread[span_2](start_span)[span_2](end_span)
checkpointer = MemorySaver()[span_3](start_span)[span_3](end_span)
app = builder.compile(checkpointer=checkpointer)

Running and Resuming the Workflow
1. Initial Execution (Hits the Interrupt)
config = {"configurable": {"thread_id": "tx-1001"}}[span_4](start_span)[span_4](end_span)

# Trigger a run with an amount that exceeds the threshold
result = app.invoke({"recipient": "supplier@acme.com", "amount": 2500.0}, config)

Output:
[Node] Checking transfer of $2500.0 to supplier@acme.com...

Execution halts at the interrupt(...) line. The node has not completed, and state has not transitioned to END.
2. Inspecting the Pending Interrupt Request
You can inspect the interrupt payload raised by the node:
state_snapshot = app.get_state(config)

# snapshot.tasks lists the interrupted task and its payload
task = state_snapshot.tasks[0]
for inter in task.interrupts:
    print("Interrupt Prompt:", inter.value)

Output:
Interrupt Prompt: {'message': 'High-value transfer of $2500.0 requires approval.', 'recipient': 'supplier@acme.com'}

3. Resuming with the User's Decision via Command(resume=...)
To resume execution, pass Command(resume=<value>) into app.invoke() using the same thread_id. The node picks up execution directly after interrupt():
# Pass True (or False) directly back into the waiting interrupt() call
final_result = app.invoke(Command(resume=True), config)

print("Final State:", final_result)

Output:
Final State: {'recipient': 'supplier@acme.com', 'amount': 2500.0', 'confirmed': True, 'status': 'completed'}

Key Takeaways
 * Precise Placement: You can invoke interrupt() anywhere inside standard Python control flow (if statements, loop iterations, or after specific API calls).
 * Two-Way Communication: The argument passed to interrupt(payload) is sent out to the client, and the argument passed to Command(resume=value) is returned directly into the node variable.
 * Requirements: A checkpointer (MemorySaver, SqliteSaver, etc.) and a consistent thread_id are required to maintain state across pause and resume calls.
