Human-in-the-Loop (HITL) in LangGraph allows a workflow to pause execution automatically before or after sensitive actions, inspect or modify the state, and resume once a human provides input, approval, or corrections.
Core Mechanics of HITL
HITL relies on two foundational features in LangGraph:
 * Checkpointers (checkpointer): Saves graph state snapshots to memory or a database at every step, keyed by a thread_id.
 * Breakpoints (interrupt_before or interrupt_after): Flags passed to .compile() specifying which nodes should automatically halt execution.
When a graph encounters a breakpoint:
 * It persists the state and exits execution cleanly.
 * A human inspects the current snapshot using graph.get_state(config).
 * The human can approve as-is or patch the pending action using graph.update_state(config, ...).
 * Calling graph.invoke(None, config) resumes execution from the paused step.
Step-by-Step Example: Approval Gate for an Email Dispatcher
This scenario models an agent drafting an email and pausing for human review before calling the dispatch node.
1. Define State and Nodes
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver

class EmailState(TypedDict):
    recipient: str
    subject: str
    body: str
    status: str

def draft_email_node(state: EmailState) -> dict:
    print("[Agent] Drafting email...")
    # LLM or logic produces a draft
    return {
        "recipient": "client@example.com",
        "subject": "Invoice Reminder",
        "body": "Hi, please settle your overdue invoice of $500 immediately.",
        "status": "pending_approval"
    }

def send_email_node(state: EmailState) -> dict:
    print(f"[System] Sending email to {state['recipient']}...")
    print(f"Subject: {state['subject']}")
    print(f"Content: {state['body']}")
    return {"status": "sent"}

2. Assemble Graph with an Interruption Point
builder = StateGraph(EmailState)
builder.add_node("draft_email", draft_email_node)
builder.add_node("send_email", send_email_node)

builder.add_edge(START, "draft_email")
builder.add_edge("draft_email", "send_email")
builder.add_edge("send_email", END)

# Compile with a checkpointer and configure breakpoint before 'send_email'
checkpointer = MemorySaver()
app = builder.compile(
    checkpointer=checkpointer,
    interrupt_before=["send_email"]
)

3. Run the Initial Phase (Execution Pauses)
config = {"configurable": {"thread_id": "thread-email-001"}}

# Start execution
app.invoke({}, config)

Output:
[Agent] Drafting email...

The graph stops here because interrupt_before=["send_email"] halted execution right before entering the send_email node.
4. Human Review & State Intervention
A human can inspect what the agent drafted before it is sent:
snapshot = app.get_state(config)

print("Next Node Scheduled:", snapshot.next)
print("Current Draft Body :", snapshot.values["body"])

Output:
Next Node Scheduled: ('send_email',)
Current Draft Body : Hi, please settle your overdue invoice of $500 immediately.

Scenario A: Human Edits the Draft Mid-Flight
If the tone is too aggressive, the human updates the state before resuming:
# Human softens the email body
app.update_state(
    config,
    {"body": "Hi, just a friendly reminder regarding invoice #102. Thanks!"}
)

Scenario B: Resume Execution
Call invoke(None, config) to continue where it stopped:
# Passing None tells LangGraph to continue from the last checkpoint
app.invoke(None, config)

Output:
[System] Sending email to client@example.com...
Subject: Invoice Reminder
Content: Hi, just a friendly reminder regarding invoice #102. Thanks!

Summary of Common HITL Patterns
 * Approval Gate: The human checks snapshot.values and resumes with app.invoke(None, config) if approved, or halts execution if rejected.
 * State Editing / Correction: The human modifies tool arguments or draft content using app.update_state() before resuming.
 * Dynamic Interruption (interrupt()): In modern LangGraph versions, you can also raise an inline interrupt(...) call inside any node to prompt the caller for dynamic data (e.g., asking the human for missing parameters or two-factor confirmation) rather than pausing at pre-set node boundaries.
