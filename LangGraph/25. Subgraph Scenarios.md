# LangGraph Subgraphs
- In LangGraph, subgraphs are compiled graphs inserted as a single node inside a larger parent graph. 
- They function like functions or modules in traditional software engineering, drawing a clean boundary around a subset of your AI workflow. [1, 2, 3] 

We should use LangGraph subgraphs in the following core scenarios:

## 1. Isolated State Management (Different Schemas)
- By default, every node in a flat LangGraph shares the exact same global state dictionary. - When building complex workflows, we frequently want individual agents or processes to maintain private information without cluttering or accidentally overwriting the parent graph's state. [4] 


* **Private Message Histories**: 
- In a multi-agent chat system, an individual agent might need to swap multiple messages back and forth with an LLM to formulate an answer. 
- A subgraph allows it to hold a private chat history that disappears or is condensed before returning the final answer to the parent graph. [4, 5] 
* **State Transformation**:
- If a sub-process operates on a completely different data schema (e.g., the parent tracks a user_id and booking_status, but the checkout sub-process needs items, tax_rate, and subtotal), wrapping it in a subgraph isolates those specific keys. [2, 5] 
 

## 2. Multi-Agent Systems with Specialized Teams
- If we are designing a complex application, a single supervisor agent trying to orchestrate ten different specialized tools or nodes becomes highly prone to error. Subgraphs let you group specialized agents into discrete units. [6] 


* **The "Agent-as-a-Node" Pattern**: 
- Instead of exposing a dozen small nodes to the root router, you can route to a "Research Agent" node (which internally runs a multi-node subgraph of query rewrite → web search → critique). [7, 8] 
* **Domain Segregation**:
- In a Travel Planner App, the parent graph coordinates the high-level itinerary. 
- It passes control to a Flight Booking Subgraph, a Hotel Booking Subgraph, and a Restaurant Recommendation Subgraph.
- Each team works independently until their specific task is done. [6, 8] 

## 3. Target Reusability Across Different Applications
- If a specific multi-step logic sequence needs to be used in multiple workflows, building it as a subgraph allows you to write it once, test it independently, and plug it in anywhere. [2] 


* **Shared Utility Pipelines**:
- A multi-step Pricing Calculator (that fetches discounts, applies regional tax rules, and cross-references user loyalty tiers) can be packaged as a single subgraph node. 
- We can seamlessly drop this identical node into both a Checkout Graph and a B2B Sales Quote Graph. [2] 


## 4. Fine-Grained Human-in-the-Loop (HITL) Controls
- When an AI application requires a human to review, approve, or edit its output, subgraphs make the pausing and state-rewinding mechanisms highly manageable. [9, 10] 


* **Review-and-Loop Scenarios**:
- Imagine a Software Development Assistant where a subgraph handles the technical drafting (code generation → test suite compilation → error correction loop).
- Once the subgraph finishes drafting the code, the parent graph hits an interrupt node for a senior developer's review. 
- If the human rejects it, the parent loops back and re-triggers the generation subgraph with the human's feedback. [9, 10, 11] 


## 5. Team-Level Abstraction and Clean Architecture
- As development teams scale, having everyone edit one massive, flat graph file introduces merge conflicts and debugging headaches.

* **Separation of Concerns**:
- One team can own the core user-facing chat orchestration (the Parent Graph) while providing a strict contract of inputs and outputs to an infrastructure team. 
- The infrastructure team can freely expand or change an internal Data Retrieval Subgraph without breaking or needing to modify the main orchestration flow. [3, 8] 

------------------------------
## LangGraph Subgraph Patterns: At a Glance

| Feature / Scenario | Shared State Subgraph | Isolated State Subgraph |
|---|---|---|
| How it's integrated | Added directly via builder.add_node("name", compiled_subgraph) | Invoked inside a wrapper node function that maps states manually |
| State Relationship | Subgraph keys match/overlap with Parent Graph keys | Subgraph has entirely unique or independent keys |
| Best Used For | Continuous pipelines like data preprocessing or multi-step calculations | Multi-agent setups requiring strict privacy or specialized data structures |
