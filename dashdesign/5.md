This is a **classic polyglot persistence** challenge. You need to combine **real-time transactional data** (MongoDB) with **hierarchical/static data** (PostgreSQL) for a **user-specific dashboard**.

Here's a **practical, production-ready approach** using **3 strategies** – from simplest to most scalable.

---

## 🎯 Strategy 1: Application-Level Join (Simplest)

### Flow:
1. **Query PostgreSQL** – Get the logged-in user's hierarchy (all descendant IDs)
2. **Query MongoDB** – Aggregate transactions filtering on those IDs
3. **Merge results** – Apply drill-down filters in the app

### Step-by-Step Implementation:

#### A. Get hierarchy from PostgreSQL
```sql
-- For user Jane Smith (party_id = 4) – get all descendants AND ancestors
WITH user_hierarchy AS (
    -- Get all descendants (if user is agency head)
    SELECT child_id AS party_id
    FROM hierarchy
    WHERE path @> ARRAY[4]  -- All nodes under Jane
      AND child_id != 4
    UNION
    -- Include the user themselves
    SELECT 4 AS party_id
    UNION
    -- Get ancestors (for parent roll-ups if needed)
    SELECT parent_id
    FROM hierarchy
    WHERE child_id = 4
)
SELECT array_agg(party_id) AS all_related_ids
FROM user_hierarchy;
```
**Result:** `[4, 3, 2, 1]` – all parties Jane has access to.

#### B. MongoDB Aggregation with Hierarchy Filter
```javascript
// Pass the party_ids array from PostgreSQL
const partyIds = [4, 3, 2, 1];

// Build dynamic filters based on drill-down selections
const filters = {
    "broker.party_id": { $in: partyIds },
    "application_date": { $gte: new Date("2026-01-01") }
};

// Apply drill-down filters (UI selections)
if (req.query.state) filters["address.state"] = req.query.state;
if (req.query.market_category) filters["product.category"] = req.query.market_category;
if (req.query.status) filters["status"] = req.query.status;

// Aggregation pipeline
const pipeline = [
    { $match: filters },
    {
        $facet: {
            // Total Applications
            total_applications: [
                { $count: "value" }
            ],
            // Total Renewals
            total_renewals: [
                { $match: { transaction_type: "renewal" } },
                { $count: "value" }
            ],
            // Total Commissions
            total_commissions: [
                { $group: { _id: null, total: { $sum: "$commission_amount" } } }
            ],
            // Breakdown by State (for drill-down)
            by_state: [
                { $group: { 
                    _id: "$address.state", 
                    count: { $sum: 1 },
                    commissions: { $sum: "$commission_amount" }
                }},
                { $sort: { count: -1 } }
            ],
            // Breakdown by Market Category
            by_market: [
                { $group: { 
                    _id: "$product.category", 
                    count: { $sum: 1 },
                    commissions: { $sum: "$commission_amount" }
                }},
                { $sort: { count: -1 } }
            ],
            // Breakdown by Status
            by_status: [
                { $group: { 
                    _id: "$status", 
                    count: { $sum: 1 } 
                }},
                { $sort: { count: -1 } }
            ]
        }
    }
];

const results = await db.collection('transactions').aggregate(pipeline).toArray();
```

#### C. Return API Response
```javascript
// Combine and format results
const dashboard = {
    total_applications: results[0].total_applications[0]?.value || 0,
    total_renewals: results[0].total_renewals[0]?.value || 0,
    total_commissions: results[0].total_commissions[0]?.total || 0,
    breakdowns: {
        by_state: results[0].by_state,
        by_market: results[0].by_market,
        by_status: results[0].by_status
    }
};
```

## 🔄 Strategy 2: Pre-Aggregated Materialized Views (Scalable)

### Concept:
Store **pre-calculated metrics** in MongoDB for common query patterns, updated via **change streams** or **scheduled jobs**.

### Implementation:

#### A. Create a Materialized Collection in MongoDB
```javascript
// Collection: dashboard_metrics
{
    "_id": "2026-08_4",  // {period}_{party_id}
    "party_id": 4,
    "period": "2026-08", // Monthly aggregation
    "metrics": {
        "total_applications": 45,
        "total_renewals": 12,
        "total_commissions": 34567.89,
        "by_state": {
            "TX": { count: 30, commissions: 23456.78 },
            "CA": { count: 15, commissions: 11111.11 }
        },
        "by_market": {
            "PPO": { count: 25, commissions: 20000.00 },
            "HMO": { count: 20, commissions: 14567.89 }
        },
        "by_status": {
            "approved": 30,
            "pending": 10,
            "rejected": 5
        }
    },
    "last_updated": ISODate("2026-08-13")
}
```

#### B. Update via Scheduled Job (Node.js)
```javascript
// Run daily or after each transaction
async function refreshMetrics() {
    const partyIds = await getPostgreSQLHierarchy(); // All active parties
    
    for (const partyId of partyIds) {
        // Get all descendants for this party
        const descendants = await getDescendants(partyId);
        
        const pipeline = [
            { $match: { 
                "broker.party_id": { $in: descendants },
                "application_date": { $gte: new Date("2026-08-01") }
            }},
            // Same $facet aggregation as Strategy 1
        ];
        
        const metrics = await db.collection('transactions').aggregate(pipeline).toArray();
        
        // Upsert into dashboard_metrics
        await db.collection('dashboard_metrics').updateOne(
            { 
                party_id: partyId,
                period: "2026-08"
            },
            { 
                $set: { 
                    metrics: metrics[0],
                    last_updated: new Date()
                }
            },
            { upsert: true }
        );
    }
}
```

#### C. Dashboard Query (Lightning Fast)
```javascript
// User selects "August 2026"
const dashboard = await db.collection('dashboard_metrics').findOne({
    party_id: 4,
    period: "2026-08"
});

// Apply additional filters client-side or with a secondary aggregation
if (req.query.status) {
    // Filter the pre-aggregated breakdown
    dashboard.metrics.by_status = {
        [req.query.status]: dashboard.metrics.by_status[req.query.status]
    };
}
```

## 🚀 Strategy 3: Hybrid Realtime + Cached (Production-Ready)

### Architecture:
```
┌─────────────────────────────────────────────────────┐
│            User Requests Dashboard                  │
└─────────────────┬───────────────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────────────┐
│        1. PostgreSQL Query (Hierarchy)             │
│         - Get all descendant IDs                   │
│         - Cache in Redis (TTL: 1 hour)            │
└─────────────────┬───────────────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────────────┐
│        2. Check Redis Cache                        │
│         - Key: dashboard:{partyId}:{period}       │
│         - If exists → return cached result        │
└─────────────────┬───────────────────────────────────┘
                  │ (Cache miss)
                  ▼
┌─────────────────────────────────────────────────────┐
│        3. MongoDB Aggregation (Realtime)           │
│         - Only last 7 days (hot data)             │
│         - Historical data from materialized view  │
└─────────────────┬───────────────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────────────┐
│        4. Apply Drill-Down Filters                │
│         - State, Market Category, Status          │
│         - Re-aggregate if needed                  │
└─────────────────┬───────────────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────────────┐
│        5. Store in Redis (TTL: 5 minutes)         │
│         - Return to user                          │
└─────────────────────────────────────────────────────┘
```

### Implementation:

```javascript
// Node.js API endpoint
async function getBrokerDashboard(req, res) {
    const { partyId, period = 'current_month' } = req.user;
    const { state, marketCategory, status } = req.query;
    
    // Step 1: Get hierarchy from PostgreSQL with caching
    const cacheKey = `hierarchy:${partyId}`;
    let partyIds = await redis.get(cacheKey);
    
    if (!partyIds) {
        // Query PostgreSQL
        const result = await pg.query(`
            WITH RECURSIVE hierarchy AS (
                SELECT child_id FROM hierarchy WHERE parent_id = $1
                UNION
                SELECT h.child_id 
                FROM hierarchy h
                JOIN hierarchy ON hierarchy.child_id = h.parent_id
            )
            SELECT array_agg(child_id) AS party_ids FROM hierarchy
        `, [partyId]);
        
        partyIds = result.rows[0].party_ids;
        await redis.setex(cacheKey, 3600, JSON.stringify(partyIds));
    } else {
        partyIds = JSON.parse(partyIds);
    }
    
    // Step 2: Check dashboard cache
    const dashKey = `dashboard:${partyId}:${period}:${state || 'all'}:${marketCategory || 'all'}:${status || 'all'}`;
    let dashboardData = await redis.get(dashKey);
    
    if (!dashboardData) {
        // Step 3: Build MongoDB aggregation with drill-down filters
        const matchStage = {
            "broker.party_id": { $in: partyIds },
            "application_date": { $gte: getPeriodStart(period) }
        };
        
        if (state) matchStage["address.state"] = state;
        if (marketCategory) matchStage["product.category"] = marketCategory;
        if (status) matchStage["status"] = status;
        
        // Separate pipelines for realtime vs historical
        const [realtime, historical] = await Promise.all([
            // Last 7 days – fresh aggregation
            db.collection('transactions').aggregate([
                { $match: { ...matchStage, application_date: { $gte: new Date(Date.now() - 7*24*60*60*1000) } } },
                { $group: { _id: null, count: { $sum: 1 }, commissions: { $sum: "$commission_amount" } } }
            ]).toArray(),
            
            // Historical – from materialized view
            db.collection('dashboard_metrics').findOne({
                party_id: { $in: partyIds },
                period: getPeriodString(period)
            })
        ]);
        
        // Combine results
        dashboardData = {
            total_applications: (realtime[0]?.count || 0) + (historical?.metrics?.total_applications || 0),
            total_commissions: (realtime[0]?.commissions || 0) + (historical?.metrics?.total_commissions || 0),
            // ... combine other metrics
        };
        
        // Step 5: Cache
        await redis.setex(dashKey, 300, JSON.stringify(dashboardData));
    } else {
        dashboardData = JSON.parse(dashboardData);
    }
    
    res.json(dashboardData);
}
```

## 🧠 Which Strategy to Choose?

| Scenario | Recommendation |
|----------|---------------|
| **< 100K transactions/month, < 1000 brokers** | Strategy 1 (Application join) – simplest |
| **100K-1M transactions, frequent dashboard views** | Strategy 2 (Materialized views) – best performance |
| **> 1M transactions, realtime needs, complex drill-downs** | Strategy 3 (Hybrid) – production-grade |
| **Your current state** | Start with **Strategy 1**, optimize to **Strategy 3** as you scale |

## ⚡ Performance Optimization Tips

1. **Index MongoDB** for your most common filters:
```javascript
db.transactions.createIndex({ "broker.party_id": 1, "application_date": -1 });
db.transactions.createIndex({ "address.state": 1, "application_date": -1 });
db.transactions.createIndex({ "product.category": 1 });
```

2. **Use projection** – only return what you need:
```javascript
{ $project: { 
    "broker.party_id": 1, 
    "commission_amount": 1, 
    "address.state": 1,
    "product.category": 1,
    "status": 1 
}}
```

3. **Limit aggregation scope** – always filter by date range first.
