You're absolutely right to be concerned. **Yes, there is significant latency with on-demand federated queries**, and it's the #1 trade-off you need to manage. 

Here’s the reality of what happens at request time:

- **Cold Start & Network Overhead**: Each query triggers live network calls to S3/Azure/HTTP endpoints. Object storage (S3) has **200-500ms latency** just for listing files, plus you're parsing Parquet/CSV on-the-fly—no indexes exist.
- **No Indexes on External Data**: While `$lookup` pushes filters to your MongoDB collections (fast), it **cannot push filters** to S3 or HTTP sources. The federation engine must scan entire external datasets to join them.
- **Real-World Impact**: A dashboard loading 5 widgets could easily take **5-15 seconds**, which is unacceptable for a broker dashboard. For example, a simple query joining 1M transactions (MongoDB) with broker tiers (S3 CSV) often exceeds 10 seconds.

### How Do You Fix This? (3 Practical Solutions)

**1. Pre-Join via Scheduled Materialized Views (Best for Performance)** 
Create an aggregation pipeline that runs **every 5-15 minutes** and writes the fully joined dataset into a dedicated MongoDB collection using `$merge`. Your dashboard queries *only* this pre-computed collection—queries return in **<100ms**.

**2. Implement Caching at the Application Layer**
Use **Redis** or **MongoDB's in-memory cache** with a TTL (e.g., 5 minutes). Store the final aggregated results (like "total renewals per agency tier") so the 10-second federated query runs only once per 100 users instead of every request.

**3. Hybrid Strategy (Most Practical)**
- Keep **high-frequency metrics** (daily totals, tier counts) in a pre-aggregated MongoDB collection (refreshed hourly).
- Use **on-demand federation** only for deep-dive ad-hoc filters (e.g., "show me this specific broker's history"), which runs rarely and with acceptable wait time.

### The Golden Rule
**Never** use federation directly for your dashboard's main landing page. Always pre-aggregate for the most frequently viewed metrics. For your use case, I'd recommend **Solution #1**—schedule a job every 5 minutes to combine transactions, agency hierarchy, and broker tiers into a single collection, then let your dashboard query that lightning-fast.
